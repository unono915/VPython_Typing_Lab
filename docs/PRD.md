## 1. 배경

이 과목은 17주 동안 학생이 계속 **코드를 직접 타이핑**한다.

- 2~7주차 VPython — `sphere`, `vec(0,0,0)`, `make_trail=True`
- 8~10주차 바이브코딩 — 프롬프트와 코드 수정
- 11~17주차 ESP32 — `digitalWrite`, `analogRead`

그런데 고1 학생 다수가 **영타가 느리고, 특히 기호 입력이 서툴다.**
실제로 실습에서 시간을 잡아먹는 건 개념 이해가 아니라 다음 세 가지다.

1. 괄호 `(` `)` 를 찾느라 손이 멈춤
2. `_` (언더바)와 `-` (하이픈)를 혼동
3. `.` `,` `=` 를 오타 내고 원인을 못 찾음

일반 타자 연습 사이트는 **한글 산문**을 치게 한다. 이 과목에 필요한 건 다르다.
교과 어휘와 기호로 연습해야 실습 시간에 바로 값을 한다.

## 2. 목표 / 비목표

### 목표
- G1. 학생이 **VPython·ESP32 코드에 실제로 나오는 문자열**로 영타를 연습한다.
- G2. 연습 결과를 **수치로 확인**하고, **자기가 자주 틀리는 문자**를 알게 된다.
- G3. 학기 초와 학기 말 기록을 비교해 **성장을 스스로 확인**한다.
- G4. 교사가 **링크 하나만 주면** 수업에서 즉시 굴러간다.

### 비목표 (하지 않는 것)
- N1. **VPython 문법을 가르치지 않는다.** 뜻 설명·해설 없음. 타이핑만.
- N2. 한글 타자 연습을 지원하지 않는다. (영타 + 기호 전용)
- N3. **학생에게** 계정·로그인을 요구하지 않는다.
- N4. 반·학번·이름과 연습 결과 외의 개인정보는 수집하지 않는다.

> **v2.0 에서 뒤집힌 결정**
> v1.0 의 N3·N4 는 *"서버를 두지 않는다 / 기록을 수집하지 않는다"* 였다.
> 교사가 학생별 수행을 확인할 방법이 없다는 요구가 나와 **서버 수집을 도입**했다.
> 대신 원래 의도(학생 부담 0, 개인정보 최소)는 다음으로 지킨다.
> · 학생은 여전히 로그인하지 않는다 — 반과 이름만 고른다
> · 수집 항목을 12개 필드로 한정하고 DB CHECK 로 강제한다
> · 학생은 **쓰기만** 가능하고, 자기 기록조차 다시 읽지 못한다
> · `config.js` 의 `sync: false` 로 언제든 완전 오프라인으로 되돌릴 수 있다

#### 등급 산정

레벨마다 문자열 길이와 기호 밀도가 달라 속도가 다르므로 **기준선을 레벨별로 분리**한다.

| 기준 타수 | S | A | B | C |
|---|---|---|---|---|
| LEVEL 1 · 낱말 | 260 | 200 | 150 | 100 |
| LEVEL 2 · 기호 | 200 | 155 | 115 | 75 |
| LEVEL 3 · 코드 | 170 | 130 | 95 | 60 |

**정확도 게이트** — 속도보다 정확도를 먼저 잡게 만드는 장치.

```
정확도 < 95%  →  S 불가
정확도 < 90%  →  A 불가
정확도 < 80%  →  B 불가
```

즉 타수가 아무리 높아도 정확도 79%면 최고 C다. "정확도 먼저"라는 교육 메시지를 규칙으로 강제한다.

### 5.2 문제 세트 정의

```
LEVEL 1 · 낱말        sphere  vector  opacity  rate  scene  ...        (~40개 중 12개 출제)
LEVEL 2 · 기호 섞기   color.red  vec(0,0,0)  make_trail=True  ...      (~23개 중 10개 출제)
LEVEL 3 · 코드 한 줄  ball = sphere(pos=vec(0,0,0), radius=1)  ...     (~12개 중 8개 출제)
```

- 세트는 `assets/js/data.js` 한 파일에 분리한다. **교사가 코드를 몰라도 단어를 고칠 수 있게** 한다.
- 한 판은 **1~2분**을 넘지 않아야 한다. (수업 20분 안에 여러 판 가능해야 함)

#### 출제 수 재조정 (v2.3)

초기값(12/10/8)을 실제 소요 시간으로 검산하니 양끝이 목표를 벗어났다.

| 단계 | 이전 | 이후 | 글자수 | 초보(80타) | 빠름(250타) |
|---|---|---|---|---|---|
| 낱말 | 12 | **18** | 95 | 71초 | 23초 |
| 기호 섞기 | 10 | 10 | 112 | 84초 | 27초 |
| 코드 한 줄 | 8 | **6** | 161 | 121초 | 39초 |

- 낱말이 63자(빠른 학생 **15초**)여서 **타수가 들쭉날쭉했다.** 짧을수록 측정 분산이 커져 등급 기준이 흔들린다.
- 코드 한 줄은 초보에게 **161초** 로 2분을 넘겨 지쳤다.

### 5.5 입력 모드 점검 (F13)

고1 학생이 영타 연습에서 실제로 겪는 첫 번째 장벽은 **한/영 키와 CapsLock** 이다.
이 상태로 치면 정확도가 0%대로 찍히고, 학생은 자기가 못하는 줄 안다.

| 상태 | 감지 방법 | 동작 |
|---|---|---|
| CapsLock | `KeyboardEvent.getModifierState('CapsLock')` | 경고 표시. 새 입력을 되돌리고 타이머를 시작하지 않음. **백스페이스는 허용** |
| 한글 IME | `compositionstart` 이벤트 + 입력값의 한글 유니코드 검사 | 경고 표시. 한글을 제거하되 **오타로 세지 않음** |

> IME 상태를 직접 읽는 웹 표준 API 는 없다. 그래서 CapsLock 은 *사전에*,
> 한글은 *들어온 직후에* 잡는 두 가지 방식을 병행한다.

**핵심 규칙: 잘못된 입력 모드로 친 글자는 오타로 집계하지 않는다.**
학생 잘못이 아닌 것으로 점수를 깎으면 이 도구의 목적에 어긋난다.

### 5.6 공용 PC 문제 (F16)

**v2.0 에서 발견된 데이터 무결성 결함.**

컴퓨터실 PC 는 교시마다 다른 학생이 쓴다. 이름을 `localStorage` 에 저장해 두면
다음 교시 학생의 기록이 **앞사람 이름으로 전송된다.** 교사 대시보드의 데이터가 조용히 오염된다.

| 해결안 | 판단 |
|---|---|
| 날짜가 바뀌면 초기화 | ✗ 같은 날 2교시·4교시에 다른 반이 쓰면 못 잡는다 |
| 매번 새로 입력 | ✗ 20분 수업에서 매번 타이핑은 낭비 |
| **열 때마다 한 번 확인** | ✓ 클릭 한 번. 확실하고 빠르다 |

**v2.5 — 확인 바를 시작 모달로 교체했다.**
상단 입력칸은 그냥 지나치기 쉬웠다. 학생이 이름을 안 넣고 연습을 끝내면 기록이 남지 않는다.
그래서 접속 시 모달로 먼저 받는다.

| 상태 | 모달 |
|---|---|
| 저장된 정보 없음 | 반·학번·이름 **입력** (반·이름 필수) |
| 저장된 정보 있음 | *"이 정보가 맞나요?"* → 네 / 아니요(다시 입력) |

- **받기 전에는 전송하지 않는다** (`identityOk = false` 로 시작)
- 모달이 떠 있는 동안 키 입력이 연습칸으로 새지 않는다
- **"그냥 연습만 할게요"** 로 건너뛸 수 있다. 연습은 되고 기록만 안 남는다 —
  수업과 무관한 사람이나 시연용을 막지 않기 위한 탈출구다
- `sync: false` 면 모달 자체가 뜨지 않는다

### 5.7 이름 정규화

`김민준` 과 `김 민준` 이 대시보드에서 다른 학생으로 잡히면 집계가 무너진다.
앞뒤 공백을 제거하고 중간 연속 공백을 하나로 줄인다. 학번은 공백을 전부 제거한다.

## 6. 데이터 설계 (v2.0)

### 6.1 테이블

`public.runs` — 한 판이 한 행. 12개 필드.

```
class_code  student_name  student_no  level_id  level_name  grade
kpm  accuracy  errors  best_combo  seconds  chars
```

전 필드에 CHECK 제약을 걸어 **클라이언트를 신뢰하지 않는다.**
(예: `kpm between 0 and 2000`, `grade in ('S','A','B','C','D')`)

### 6.2 권한 (RLS)

| 역할 | INSERT | SELECT | UPDATE | DELETE |
|---|---|---|---|---|
| `anon` (학생) | ✅ | ❌ | ❌ | ❌ |
| `authenticated` · 미등록 | ❌ | ❌ | ❌ | ❌ |
| `authenticated` · `teachers` 등록 | ❌ | ✅ | ❌ | ✅ |

학생은 자기 기록조차 다시 읽을 수 없다. 남의 점수를 보거나 고치는 경로가 없다.

#### v2.2 에서 막은 구멍

v2.1 까지는 `authenticated` 이면 무조건 읽을 수 있었다. 그런데 이 프로젝트는
`disable_signup: false` — **공개 가입이 열려 있다.** 공개 키는 페이지 소스에 있으므로
**주소를 아는 사람이 스스로 가입해 미성년자 기록을 전부 볼 수 있었다.**

→ `public.teachers` 허용목록을 두고, **로그인 자체를 자격에서 분리**했다.

처음에는 `is_teacher()` 를 `SECURITY DEFINER` 로 만들었으나, 그러면 `/rest/v1/rpc/is_teacher`
로 노출되어 어드바이저가 경고했다. **`teachers` 에 "자기 행만 읽기" 정책**을 주는 쪽으로
바꾸니 함수가 필요 없어졌고 경고 3건이 모두 사라졌다. 대시보드는 `GET /rest/v1/teachers`
결과가 1건인지로 권한을 판별한다.

#### 검증 (역할 시뮬레이션)

| 상황 | teachers | runs | student_summary |
|---|---|---|---|
| 등록된 교사 | 1 (자기 행) | 1 | 1 |
| 스스로 가입한 외부인 | 0 | **0** | **0** |
| 익명(학생) | 0 | 0 | 0 |

외부인의 `DELETE` 는 0행, 학생의 `INSERT` 는 정상 1행으로 확인했다.

### 6.3 검증 결과

REST API 로 직접 확인했다.

- 익명 SELECT → `[]` (행이 있어도 안 보임)
- 익명 UPDATE / DELETE → 204 를 반환하지만 **실제로는 아무 행도 바뀌지 않음** (RLS 가 조용히 필터링)
- 익명 INSERT → 201
- 범위 밖 값 INSERT → 400 `violates check constraint "runs_kpm_range"`

### 6.4 교사 인증

Supabase Auth (이메일 + 비밀번호). 계정은 교사가 대시보드에서 **직접** 만든다.
토큰은 `sessionStorage` 에만 두고 탭을 닫으면 사라진다.

### 6.5 조회 상한 (F21)

대시보드는 한 번에 2,000행을 가져온다. 실제 규모를 계산하면,

```
30명 × 12반 × 3판 = 하루 1,080행  →  이틀이면 상한 초과
```

v2.2 까지는 초과분이 **조용히 잘렸다.** 게다가 기간 필터가 클라이언트에서만 동작해
"전체" 를 골라도 최근 2,000건만 보였다. **참여한 학생이 미참여로 보이는** 상황이다.

수정
- 기간 필터를 **서버 쿼리**(`created_at=gte.`)로 옮기고, 바뀌면 다시 조회한다
- `Prefer: count=exact` 로 전체 건수를 받아 **잘렸으면 눈에 띄게 알린다**

실제 3,000행을 넣어 확인했다 — "전체" 는 경고, "오늘"(1,412행)은 정상.

### 6.6 업적을 저장하지 않고 다시 계산하는 이유 (F22)

업적은 학생 브라우저의 `localStorage` 에만 있었다. 교사가 보려면 두 가지 길이 있었다.

| 방법 | 판단 |
|---|---|
| 학생이 획득한 업적을 함께 전송 | ✗ 클라이언트가 보낸 값을 믿어야 한다. 컬럼도 늘어난다.<br>✗ 이미 쌓인 기록에는 소급되지 않는다 |
| **기록에서 다시 계산** | ✓ 8종 모두 `runs` 의 값만으로 판정 가능하다 |

8종 전부가 저장된 필드의 함수다.

```
첫 타      → 기록 1건 이상          무결점  → errors = 0
콤보 50/100 → best_combo             속사    → kpm >= 200
정밀       → accuracy >= 98          기호    → level_id != 'words' and errors <= 3
삼단 완주  → level_id 세 종류가 모두 존재
```

판정 규칙은 `data.js` 의 `badges[]` **한 곳**에만 있고 학생 화면과 교사 화면이 같은 정의를 읽는다.
규칙을 바꾸면 양쪽이 동시에 바뀌므로 어긋날 수 없다. 스키마 변경도 필요 없었다.

## 7. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 첫 화면 표시 | 1초 이내 (총 자산 < 100KB, 이미지·폰트 없음) |
| 입력 지연 | 키 입력 → 화면 반영 16ms 이내 (매 입력마다 DOM 재구성이지만 문자열이 짧아 문제 없음) |
| 브라우저 | Chrome / Edge 최신. 학교 실습실 기준 |
| 오프라인 | HTML 파일을 더블클릭해도 연습 기능은 100% 동작. 단 `file://` 에서 브라우저가 `localStorage` 를 막으면 **기록·업적 저장만 비활성화**되고 나머지는 그대로 (예외로 죽지 않는 것이 요구사항) |
| 개인정보 | 이름은 localStorage 에만. 네트워크 전송 없음 |

## 8. 성공 기준

1. 교사가 **링크 하나**로 수업을 진행할 수 있다. 별도 안내 문서가 필요 없다.
2. 학생이 **설명 없이 30초 안에** 첫 문제를 친다.
3. 결과 화면의 "가장 많이 틀린 문자" 상위 3개 중 **2개 이상이 기호**로 나온다.
   → 이 도구가 겨냥한 문제가 실재함을 확인하는 지표.
4. 학기 초 대비 학기 말 평균 타수가 **상승**한다.

## 10. 배포

**GitHub Pages · Deploy from a branch (`main` / root)**

빌드 단계가 없는 정적 파일 묶음이므로 Actions 워크플로를 두지 않는다.

> **설계 판단:** 처음에는 Actions 워크플로로 배포하려 했으나,
> 저장소의 Actions 권한이 읽기 전용이라 `configure-pages` 가 Pages를 켜지 못하고 실패했다.
> 빌드할 것이 없는 프로젝트에 워크플로를 두면 **얻는 것 없이 실패 지점만 하나 늘어난다.**
> (푸시할 때마다 실패 알림 메일이 온다.) 그래서 워크플로를 걷어내고 브랜치 배포로 전환했다.

최초 1회 설정 — 저장소 **Settings → Pages**

| 항목 | 값 |
|---|---|
| Source | Deploy from a branch |
| Branch | `main` |
| Folder | `/ (root)` |

이후 `main` 에 푸시하면 1~2분 안에 자동 반영된다.

배포 주소: `https://unono915.github.io/VPython_Typing_Lab/`

`.nojekyll` 을 두어 Jekyll 전처리를 건너뛴다.
